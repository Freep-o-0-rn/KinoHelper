# Шаг 1 — диагностика сохранения прогресса

Ветка: `feature/resume-playback-diagnostics`. Рабочая версия `main` не затрагивается.

## Цель

Определить, доступен ли HTML5-элемент `video` на реальной странице просмотра, включая iframe, и сопровождается ли переключение серий корректными событиями. Инструмент **только наблюдает**: не перематывает, не сохраняет прогресс, не посылает сетевые запросы.

## Как проверить

1. Открой фильм через установленный КиноПомощник и запусти воспроизведение.
2. Нажми F12 → Console. В DevTools выбери контекст фрейма, где находится плеер, из выпадающего списка контекстов JavaScript (если он в iframe).
3. Открой файл [playback-diagnostics.js](./playback-diagnostics.js), скопируй его содержимое и вставь в Console. Если Chrome блокирует вставку, используй штатную подсказку DevTools и вставляй только код, который сам проверил.
4. Подожди 10–15 секунд, поставь на паузу, запусти снова и перемотай вручную. Для сериала дополнительно переключи серию.
5. Убедись, что есть события `video-detected`, `timeupdate`, `pause`, `seeked`, `ended` (по ситуации). Если `videoCount: 0`, проверь контекст iframe. Не делай вывод о невозможности интеграции по одному пустому контексту.
6. Сообщи, в каком фрейме найдено видео, показываются ли время и длительность, что происходит при переключении серии. Перед отправкой скриншотов скрывай персональные данные и секретные параметры URL.

Остановить диагностику: `__kinoPlaybackDiagnostics.stop()`; обновление страницы также остановит её.

## Условия перехода к шагу 2

- Установлен фактический домен/контекст плеера.
- Выяснено, можно ли читать `currentTime` и `duration`.
- Проверено, как определяется идентичность серии.
- Понятно, когда видео действительно закончилось.
- После этого можно проектировать минимальные host permissions, запись в `chrome.storage.local` и восстановление с защитой от открытия неверной серии.

Текущие временные сессии `kinoWatchSession:<tabId>` в `chrome.storage.session` остаются без изменений.
