# КиноПомощник

**Компактное расширение для Google Chrome, которое упрощает поиск фильмов и сериалов, случайный выбор по фильтрам, работу с оценками Кинопоиска и навигацию между страницами.**

## Что умеет КиноПомощник

КиноПомощник работает как в компактном popup, так и в боковой панели Chrome (Side Panel). Режим выбирается в настройках; оба используют одни и те же темы, поиск, фильтры, историю и метаданные Кинопоиска.

- **Поиск по названию** — встроенный поиск фильмов и сериалов прямо на главном экране: карточки результатов, год, постер и рейтинг (если они доступны на странице Кинопоиска), действия «Смотреть» и «Кинопоиск».
- **Фильмы и сериалы** — быстрый переход к соответствующим разделам Кинопоиска.
- **Случайный выбор** — выбор фильма или сериала с учётом текущих фильтров.
- **Динамические фильтры** — тип контента, жанр, страна, год и другие доступные параметры считываются из интерфейса Кинопоиска.
- **Исключение просмотренного** — уже просмотренные позиции можно не учитывать при случайном выборе.
- **История просмотра** — недавно открытые фильмы и сериалы сохраняются локально.
- **Оценки Кинопоиска** — отображение рейтинга и возможность поставить или изменить свою оценку от 1 до 10 при наличии авторизации на Кинопоиске.
- **Определение текущего фильма** — расширение распознаёт открытый фильм/сериал и показывает название из данных Кинопоиска.
- **Жанры и описание (1.539)** — под текущим названием отображаются жанры; справа расположена компактная кнопка «Описание ▼». Полный доступный текст со страницы Кинопоиска раскрывается по нажатию. В поисковой выдаче жанры загружаются отдельно для видимых карточек.
- **Контекстная навигация** — кнопка меняется между действиями «Смотреть» и «На Кинопоиск» в зависимости от текущей страницы.
- **Несколько тем оформления** — системная, светлая, тёмная и яркая.
- **Настройка истории** — ограничение количества записей, срока хранения и ручная очистка.
- **Popup или Side Panel** — один переключатель в настройках меняет поведение значка расширения. Боковая панель остаётся открытой рядом с сайтом, а popup работает как раньше.

## Интерфейс

Главный экран разделён на несколько компактных блоков:

1. **Поиск по названию** — результаты раскрываются прямо под строкой поиска.
2. **Фильмы / Сериалы** — быстрый переход к каталогу.
3. **Фильтры случайного выбора** — расположены непосредственно перед кнопкой случайного выбора.
4. **Случайный** — выбирает позицию с текущими фильтрами.
5. **Смотреть / На Кинопоиск** — контекстная кнопка для текущего фильма.
6. **Оценка** — рейтинг Кинопоиска и ваша оценка.
7. **Недавно просмотренные** — локальная история с быстрым повторным открытием.

Настройки открываются кнопкой ⚙️ в правой части шапки.

### Переключение Popup / Side Panel (1.536)

В **Настройки → Интерфейс** включите переключатель **«Боковая панель»**. После переключения следующее нажатие на значок КиноПомощника в панели Chrome откроет боковую панель браузера. Выключите переключатель, чтобы вернуться к обычному popup.

- По умолчанию для существующих установок сохраняется popup.
- Выбор режима хранится в `chrome.storage.local` под ключом `kinoHelperDisplayMode` и восстанавливается после перезапуска Chrome.
- Страница `sidepanel.html` использует те же сценарии `popup.js`, `search.js`, `filters.js`, `filters-ui.js`. Стили и темы общие; `sidepanel.css` адаптирует размеры и фон к ширине и высоте панели.
- В отличие от popup, боковая панель не закрывается автоматически, когда пользователь взаимодействует со страницей. После переключения с Side Panel на popup уже открытую панель можно закрыть крестиком Chrome.
- Требуется Chrome с поддержкой Side Panel API (Chrome 114+); возможность открытия по пользовательскому действию поддерживается с Chrome 116+.
- В `manifest.json` разрешение `sidePanel` используется только для открытия панели. Для выбора поведения значка применяется `chrome.action.setPopup` и `chrome.sidePanel.setPanelBehavior`.

### Адаптивная история в боковой панели (1.540)

В Side Panel блок «Недавно просмотренные» теперь подстраивается под число записей:
- При сворачивании остаётся только заголовок без пустой области.
- При раскрытии высота списка соответствует числу записей до лимита `min(48dvh, 360px)`, после которого используется внутренняя прокрутка.
- Стили ограничены `sidepanel.css`: обычный popup остаётся фиксированным по высоте и использует прежнюю высоту истории.

### Живой геометрический фон (1.537)

Только в **боковой панели** поверх фонового цвета появляется декоративная анимация:
- 12 полупрозрачных контуров: круги, треугольники, квадраты, ромбы, пятиугольники и шестиугольники;
- плавное изменение размеров, случайные изменения направления и отражения от границ панели;
- скорость **«Быстрее» (×1,4)** из предпросмотра, отрисовка до **30 кадров/с**;
- чуть более контрастные контуры для светлой и яркой тем; для тёмной — сохранена мягкая прозрачность;
- остановка при скрытии окна и статичный фон при системном `prefers-reduced-motion: reduce`.

Анимация реализована локально в `sidepanel-ambient.js` на Canvas, не использует внешние запросы и не перехватывает мышь. **Popup и механизмы поиска, постеров, истории, фильтров не изменяются.** Версия перед добавлением эффекта сохранена в ветке [stable/1.536](https://github.com/Freep-o-0-rn/KinoHelper/tree/stable/1.536).

## Установка

Расширение устанавливается в Chrome как **распакованное расширение**.

### 1. Скачайте проект

Через Git:

```bash
git clone https://github.com/Freep-o-0-rn/KinoHelper.git
```

или скачайте ZIP репозитория и распакуйте его.

### 2. Откройте страницу расширений

В адресной строке Chrome:

```text
chrome://extensions/
```

### 3. Включите режим разработчика

В правом верхнем углу включите **«Режим разработчика»**.

### 4. Загрузите расширение

Нажмите **«Загрузить распакованное расширение»** и выберите папку проекта, в которой находится `manifest.json`.

После установки КиноПомощник можно закрепить на панели Chrome.

## Как обновлять вручную без потери данных

Для локально установленного расширения важно обновлять **тот же экземпляр**, а не создавать новый.

Правильная схема:

1. Оставьте текущую папку KinoHelper на месте.
2. Обновите файлы в этой же папке через `git pull` или замените их файлами новой версии.
3. Откройте `chrome://extensions/`.
4. Нажмите кнопку **перезагрузки** у КиноПомощника.

> **Не удаляйте старое расширение перед обновлением и не загружайте новую версию из другой папки**, если хотите сохранить тот же ID расширения и его локальные данные.

Если Chrome создаёт второй экземпляр КиноПомощника с другим ID, его хранилище будет отдельным.

## Где хранятся данные

Пользовательские данные хранятся локально в профиле Chrome.

| Данные | Хранилище |
|---|---|
| История просмотренного | `localStorage` |
| Настройки интерфейса и истории | `localStorage` |
| Состояние динамических фильтров | `localStorage` |
| Состояние блока истории | `localStorage` |
| Режим открытия (popup / Side Panel) | `chrome.storage.local` |
| Технические данные расширения | `chrome.storage.local` |
| Текущая сессия просмотра | `chrome.storage.session` |

Ключевые локальные записи текущей версии:

```text
kinopoiskHistory
kinoHelperSettings
kinopoiskDynamicFilterStateV2
historyCollapsed
```

Удаление расширения или установка другого экземпляра с новым ID может привести к тому, что старое локальное хранилище больше не будет доступно новому экземпляру.

## Поиск по названию

Поиск расположен на главном экране. После ввода двух и более символов через **350 мс** выполняется запрос; Enter запускает поиск сразу.

- Поиск получает подтверждённые ID фильмов из HTML-выдачи Кинопоиска, без стороннего API-ключа. Неработающие подсказки GraphQL (`SuggestSearch`, HTTP 400) в поиске не используются.
- **Приоритет — список фильмов.** Основной запрос и подходящие продолжения запускаются вместе, до **5 поисковых HTTP-запросов одновременно**. Результаты выводятся сразу при получении каждого ответа.
- Для названий без конечного номера проверяются части **2–10**. Однословные названия дополнительно проверяются с вариантами «Двойной…» и «Тройной…». В список добавляются только фильмы с подтверждёнными ID, содержащие исходную фразу в названии.
- Как только найдено **10 релевантных результатов** и выполнен основной запрос, оставшиеся запросы прерываются. Если найдено меньше — поиск завершается после проверки всех вариантов. Общее ограничение списка — 30 фильмов.
- **Постеры подгружаются независимо** после появления соответствующих карточек: не более **2 одновременных загрузок**, чтобы сохранить сетевой приоритет поиска. Рабочий механизм постеров (страница фильма, запасные адреса, передача data URL) не менялся.
- Названия, год и рейтинг уточняются после окончания основного поискового этапа. DOM карточек не пересоздаётся при уточнении данных.
- Кэш на 10 минут сохраняет завершённую выдачу в `chrome.storage.session`, пока работает браузер. В повторном поиске используются сохранённые результаты.
- У каждой карточки остаются кнопки «Смотреть» и «Кинопоиск». Добавление в историю происходит только при выборе «Смотреть».

Диагностика убрана из интерфейса; ошибки постеров и метаданных остаются в консоли расширения. Фильтры и кнопки случайного выбора работают отдельно и не меняются поиском.

**Резервные версии:** [stable/1.534](https://github.com/Freep-o-0-rn/KinoHelper/tree/stable/1.534) — предыдущее состояние до изменения приоритетов; [stable/1.533](https://github.com/Freep-o-0-rn/KinoHelper/tree/stable/1.533) — подтверждённая пользователем рабочая версия постеров. Доступность изображений и полнота выдачи зависят от Кинопоиска.

## Как работает случайный выбор

Упрощённая схема:

```text
Фильтры пользователя
        ↓
страница каталога Кинопоиска
        ↓
чтение доступных фильтров и результатов
        ↓
случайная страница
        ↓
случайный фильм / сериал
        ↓
проверка локальной истории
        ↓
открытие выбранной позиции
```

Если включена настройка **«Не показывать просмотренные при случайном выборе»**, расширение делает несколько попыток найти позицию, которой ещё нет в истории.

## Жанры и описание (1.539)

- Информация берётся со страницы конкретного фильма или сериала по ID Кинопоиска: `/film/{id}/` или `/series/{id}/`.
- Жанры показываются под заголовком в «Сейчас смотрите» и под метаданными карточек поиска.
- Кнопка «Описание ▼» находится **справа** и по умолчанию закрыта. При открытии текст занимает не более 150 px по высоте с внутренней прокруткой.
- Поиск не ждёт загрузки жанров: сначала показываются результаты и постеры, затем жанры подгружаются отдельно, максимум по 2 запроса одновременно и только для карточек в зоне просмотра.
- Данные кэшируются на 30 минут в сессии Chrome. Если страница Кинопоиска недоступна или не содержит нужных сведений, поле не показывается; оценки и другие функции продолжают работать.
- Обе формы интерфейса (popup и Side Panel) используют один и тот же код и текущую тему.

## Оценки Кинопоиска

Для текущего фильма КиноПомощник получает:

- название;
- год;
- рейтинг Кинопоиска;
- вашу оценку, если пользователь авторизован.

Оценку можно изменить непосредственно из popup-окна кнопками **1–10**.

Для пользовательской оценки используется текущая авторизованная сессия Кинопоиска. Пароли и данные авторизации КиноПомощник не хранит.

## Приватность

КиноПомощник не имеет собственного сервера для хранения пользовательской истории.

История, настройки и фильтры сохраняются локально в браузере. Расширение взаимодействует только с ресурсами, необходимыми для работы заявленных функций: Кинопоиском и страницами, используемыми для навигации просмотра.

КиноПомощник не хранит пароли пользователя и не содержит собственного видеохостинга или видеоплеера — он выполняет навигацию между внешними страницами.

## Важно

КиноПомощник — **независимый неофициальный проект**.

Проект не является продуктом Кинопоиска и не аффилирован с владельцами сторонних сайтов, которые могут открываться через расширение. Все названия и товарные знаки принадлежат их соответствующим правообладателям.

Работоспособность отдельных функций зависит от структуры и доступности внешних сайтов. Если Кинопоиск изменит DOM, GraphQL-запросы или структуру фильтров, соответствующие функции расширения могут потребовать обновления.

## Синхронизация «Буду смотреть» (v1.566)

При подтверждённом входе в Кинопоиск список автоматически загружается из личного профиля в локальное хранилище, раздельно по ID аккаунта. Для кнопок добавления/удаления используется реальная веб-страница фильма: расширение открывает фоновую вкладку, нажимает кнопку сайта и затем проверяет `movie.userData.isPlannedToWatch`. Успех не показывается без подтверждения. Если сайт меняет интерфейс или отклоняет действие, вкладка остаётся открытой для ручного завершения операции. Данные старого локального списка сохраняются отдельно и не переносятся в чужой профиль автоматически. Фоновая загрузка зависит от доступности HTML-профиля Кинопоиска; при ошибке прежние данные не стираются.


## Завершение просмотра до титров (v1.568)

Фильм или конкретная серия помечается как просмотренная, если плеер подтверждённо достиг 90% длительности и в текущем сеансе зафиксировано 60–120 секунд реального воспроизведения (порог зависит от длительности). Не нужно досматривать длинные титры до конца. Событие seeked не завершает запись само по себе; перемотка не засчитывается как реальное время просмотра. Событие ended по-прежнему учитывается отдельно при наличии минимум 30 секунд подтверждённого воспроизведения. После завершения фильма последующие pause/pagehide не отменяют результат; осознанный повторный просмотр с начала открывает новый незавершённый таймкод. Это локальный статус KinoHelper, а не автоматическое выставление отметки на Кинопоиске.


## Завершение просмотра (v1.569 — исправление критерия)

В v1.568 порог 90% означал позицию на таймлайне, что могло приводить к ложному зачёту после перемотки. В v1.569 источник истины — объединение непересекающихся диапазонов видео, которые действительно воспроизводились через KinoHelper. Участки сохраняются между сеансами, повторное воспроизведение не увеличивает долю. 85% уникальных диапазонов — минимальное условие для автоматического завершения: дополнительно требуется подтверждённое событие окончания видео. Явное нажатие «✓ Досмотрел» в истории также позволяет вручную подтвердить завершение при 85% реально просмотренного материала либо при сохранённой позиции не менее 85% (для старых записей, где диапазоны неизвестны). Само положение ползунка никогда не вызывает автоматический зачёт. Доля на полоске прогресса — позиция плеера, а не процент фактически просмотренных сцен. Исторические записи из прошлых версий без диапазонов не превращаются автоматически в подтверждённое покрытие. Старые отметки «Просмотрено» не удаляются автоматически, потому что нельзя безошибочно восстановить их происхождение.


## Профильная синхронизация «Буду смотреть» (v1.570)

Загрузка списка идёт с персональной страницы Кинопоиска. Сначала расширение пробует фоновое чтение HTML, а при отсутствии данных проверяет страницу через обычную временную вкладку Chrome с текущей авторизацией. Фильмы и сериалы появляются в списке по мере загрузки страниц, хранятся отдельно для каждого ID профиля и входят в JSON-экспорт.

В карточке «Буду смотреть» добавлена компактная кнопка ↻ для повторной синхронизации и статус загрузки. Если Кинопоиск не предоставляет список или требует проверку, прежние записи сохраняются, ошибка показывается пользователю. Без достоверного подтверждения всех страниц расширение не сообщает о полном импорте. Обход блокировок или чтение паролей не используются.

Диаграмма «Любимые жанры» теперь рисует такие же небольшие промежутки между сегментами, как диаграмма «Мои оценки».

Важно: парсер адаптирован к нескольким встречающимся вариантам HTML/SSR профилей. Работа на конкретном авторизованном профиле должна быть подтверждена в Chrome, поскольку прямой доступ к пользовательской странице может ограничиваться Кинопоиском.


## «Буду смотреть» после реального просмотра (v1.571)

Когда KinoHelper впервые подтверждает завершение **фильма** через достоверные данные плеера или ручную кнопку «✓ Досмотрел», он проверяет список «Буду смотреть» текущего аккаунта Кинопоиска. Если фильм там есть, расширение пробует убрать его штатной кнопкой сайта, а не недокументированным запросом. Удаление считается завершённым только после проверки ответа Кинопоиска. Задание на удаление переживает перезапуск браузера; при ошибке сохраняется список и показывается сообщение в блоке «Буду смотреть». Неудавшийся клик на сайте не вызывает бесконечное открытие вкладок.

Просмотренный фильм по-прежнему учитывается локальной статистикой KinoHelper по прежним правилам; оценки, жанры и время не пересчитываются при удалении из запланированного. Отметка «Просмотрен» **на самом Кинопоиске** не выставляется без отдельного подтверждённого механизма. Завершение одной серии само по себе не удаляет целый сериал из списка.

Диаграмма жанров не группирует редкие жанры в «Другие». Для категорий даже меньше 1% можно навести курсор, нажать или выбрать с клавиатуры целую строку легенды: круг подсветит сегмент, а название и доля появятся в центре. Строки стали крупнее и остаются прокручиваемыми.


## Синхронная кнопка «Буду смотреть» (v1.572)

Кнопки из результатов поиска и карточки фильма/сериала управляют **реальным** состоянием `isPlannedToWatch` текущего авторизованного профиля Кинопоиска. Вместо поиска надписи в тексте страницы обработчик теперь находит штатную кнопку-закладку по `data-test-id="ContentActions_bookmarkButton"` (с резервными селекторами) и нажимает её. Для этого Chrome может на короткое время создать **неактивную** вкладку с карточкой фильма. Активная вкладка пользователя не переключается; временная вкладка закрывается в любом случае, даже при сбое. Это не прямой публичный API Кинопоиска.

Данные локального списка меняются **только после** повторного чтения авторизованного состояния Кинопоиска. До подтверждения на кнопке показано «↻ Сохраняем…». При неудаче показывается ошибка, а фильм остаётся в прежнем состоянии. Старые механизмы профилей, импорта, автоудаления после завершения фильма и резервного копирования сохранены. Реальное поведение DOM и реакцию Кинопоиска после клика необходимо проверить в Chrome, поскольку верстка и внутренние запросы сайта могут изменяться.


## Фоновая синхронизация Кинопоиска (v1.573)

После завершения первичного полного импорта Chrome примерно раз в минуту проверяет **первую страницу** профиля с оценками/отметками «Просмотрено» и **первую страницу** списка «Буду смотреть», без необходимости держать боковую панель открытой. Используется `chrome.alarms` и работающий по событию Manifest V3 service worker.

Новые оценки и изменения оценок на проверенной странице обновляются в локальной статистике. Отдельные отметки «Просмотрено» не прибавляют выдуманное время воспроизведения. Отметку оценки, снятую на Кинопоиске, можно убрать при разборе SSR-реакции «только просмотрено». Полностью удалённые оценки и отметки сверяются после **полного подтверждённого** обхода, который по-прежнему выполняется в фоне постранично, обычно раз в сутки.

Для «Буду смотреть» новые записи с первой страницы появляются в расширении при очередной минутной проверке. Удаления синхронизируются сразу только для достоверно одностраничного списка; в многостраничном списке удаление подтверждается полным обходом, чтобы не потерять записи, которые не видны на первой странице.

Во время первоначального импорта (например, 6/20 страниц) повторная минутная проверка не делает лишних запросов: существующий импорт уже загружает страницы каждые 30 секунд. Проверки выполняются только для верифицированного текущего аккаунта; при отказе сайта, CAPTCHA или отсутствии сети автоматически включается ограничение частоты повторов. Временные вкладки для фонового **минутного** опроса не открываются. При закрытом браузере или спящем ПК обновления могут задерживаться.


## Синхронное удаление через ✕ (v1.574)

Крестик в строке «Буду смотреть» теперь всегда отправляет **команду удаления**, а не переключает состояние в зависимости от устаревшего локального списка. Для авторизованного профиля KinoHelper вызывает ту же проверяемую операцию Кинопоиска, что и кнопка в карточке фильма: неактивная временная вкладка нажимает штатную кнопку, затем результат сверяется с `isPlannedToWatch`. Только после подтверждённого отсутствия отметки фильм исчезает из профиля в KinoHelper. Пока запрос выполняется, крестик показывает «…» и повторное нажатие запрещено; ошибка отображается в блоке без потери записи. Отдельные профили не смешиваются. Для локального списка без подтверждённого профиля сохраняется локальный режим. Изменения не затрагивают историю, рейтинги и статистику просмотра.

Параллельные запросы изменения одной закладки сериализуются, а курсор незавершённого импорта обновляется после подтверждённого удаления. Поэтому ранее считанная страница не должна вернуть удалённый фильм обратно при завершении импорта. Работу реальной кнопки сайта нужно проверить в Chrome: Кинопоиск может менять разметку или ограничивать автоматические действия.


## Производительность (v1.575)

Оптимизированы самые часто вызываемые операции без изменения пользовательских данных и алгоритмов статистики:

- **Список «Буду смотреть»:** нормализация и сортировка выполняются один раз при изменении данных, а для поиска по ID используется индекс. В синтетическом тесте 500 проверок на 350 фильмах потребовали один разбор JSON вместо 500. Этот замер оценивает конкретный участок кода, а не общее ускорение Chrome.
- **Постеры:** появление изображения обновляет только нужную карточку, не пересоздаёт весь список и не сбрасывает остальные кнопки.
- **Фоновая синхронизация:** повторно пришедший без изменений список не приводит к полной перерисовке, а ранее загруженные жанры/год/постер сохраняются, если обновление их не содержит.
- **Кнопки Кинопоиска:** убраны обязательные ожидания по 650–700 мс перед первым чтением готовой страницы и проверкой результата; последующие проверки применяют короткие нарастающие паузы. Проверка авторизованного состояния Кинопоиска **сохранена**, поэтому сетевые задержки и время загрузки страницы остаются.
- **Статистика:** изменение только счётчика импорта обновляет индикатор, не пересоздавая диаграммы.

Проверку скорости реальных запросов на Кинопоиск нужно проводить в Chrome на авторизованном аккаунте: синтетические тесты не отражают сетевые ограничения и задержки сайта. При ошибке синхронизации запись не удаляется и не добавляется без подтверждения сервера.


## Сетевые запросы, память и прогресс просмотра (v1.576)

Эта ветка **включает все оптимизации v1.575**, поэтому промежуточная установка не требуется.

- Одновременные запросы одинакового постера или метаданных теперь разделяют один сетевой запрос (in-flight deduplication), а не загружают данные повторно. При ошибке запрос можно повторить; отрицательный результат не кэшируется навсегда.
- Временный кэш изображений фонового обработчика ограничен как количеством записей (до 40), так и объёмом base64-данных (около 16 МиБ), чтобы крупные изображения не накапливались бесконтрольно. Когда кэш переполняется, удаляются давно не использовавшиеся записи.
- При сохранении прогресса просмотрa несколько связанных ключей Chrome Storage (фильмы, серии, покрытие таймкодов) читаются **одним** вызовом вместо трёх.
- Поиск фильма в «Буду смотреть» по типу/ID больше не нормализует все поля названия, постера и жанров.
- Для уже загруженного списка фоновая синхронизация пропускает одинаковые снимки, сохраняя локально уточнённые метаданные и постеры.

Оптимизации не заменяют проверку серверного ответа Кинопоиска и не изменяют правила зачёта просмотров или статистики. Ограничение скорости самого Кинопоиска и время первой загрузки незнакомых фильмов остаются внешними факторами. Тесты выполнялись на моделируемых данных; реальную скорость браузера надо проверить после установки.


## Прямое управление «Буду смотреть» без вкладок (v1.577)

Кнопка «☆ Буду смотреть», кнопка в карточке поиска и крестик ✕ в списке используют те же фоновые авторизованные GraphQL-запросы Кинопоиска, что и установка оценок. Прямые операции — `MovieSetPlannedToWatch` и `MovieRemovePlannedToWatch`. Они отправляются через существующий транспорт с Cookie-сессией и разрешёнными заголовками Origin/Referer. **При нажатии этих кнопок вкладка фильма больше не открывается.**

Операции не переключают состояние вслепую: для добавления выполняется `set`, для удаления — `remove`. Результат сервера должен быть `SUCCESS`, после чего расширение читает `isPlannedToWatch`. Только подтверждённое состояние записывается в локальный список текущего профиля. При ошибке серверного запроса или несовпадении ответа список не меняется; пользователь видит ошибку. Сохранены очереди одновременных изменений, защита от смены профиля, постраничный импорт и автоматическое удаление после подтверждённого просмотра.

Фоновый **полный импорт** списка остаётся отдельным механизмом: если HTML Кинопоиска не содержит данных, он по-прежнему может кратковременно использовать неактивную вкладку для чтения профиля. Эта процедура не связана с нажатием кнопок добавления/удаления. Полностью безвкладочный импорт можно реализовать отдельной задачей после проверки GraphQL-пагинации профиля.

Реальную работу авторизованных GraphQL-мутаций следует проверить в Chrome; структура подтверждена опубликованными примерами, но сервер Кинопоиска может изменить её.


## Кэш авторизации Кинопоиска (v1.578)

KinoHelper хранит только последний результат проверки профиля (ID, статус, время проверки), а не Cookie, токены или пароль, в общей памяти `chrome.storage.session`. Данные доступны панели, popup и service worker. Успешное подтверждение действует **2 минуты**, временная ошибка или отсутствие подтверждения — **30 секунд**. Одновременные обращения в одном контексте объединяются в один запрос; повторные обращения из разных контекстов используют общий сохранённый результат.

Открытие вкладки «Статистика» и возвращение фокуса в расширение больше не запускают принудительную проверку авторизации. Уже показанная статистика не очищается во время обычного чтения кэша. Ручная кнопка ↻ возле профиля обходит кэш. Общая минутная синхронизация также заново проверяет аккаунт один раз в начале цикла, обновляя кэш для других компонентов.

**Защита аккаунтов:** перед изменением закладки «Буду смотреть» и при привязке новой оценки к профилю выполняется новая проверка; после удалённых операций или получения очередной импортируемой страницы аккаунт сверяется перед записью данных. Ошибка проверки не приводит к привязке данных неизвестного пользователя. Для разных аккаунтов сохраняются отдельные области статистики и списка.

Кэш очищается при перезапуске браузера, отключении, обновлении или перезагрузке расширения. Этот релиз уменьшает количество повторных проверок и может снизить число CORS-сообщений, но не обещает устранить все перенаправления на Яндекс SSO: отдельные проверочные запросы по-прежнему могут получать ответы с ограничениями сервера.
